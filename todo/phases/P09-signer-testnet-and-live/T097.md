# T097 — Add the read-only query and reduce-only CLI commands

> Phase: `P09`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-20`

## Dependencies

T085, T091, T092

## Outcome

every risk-reducing control is reachable from the CLI when the Web is unavailable, and
nothing that increases a permission, an exposure limit or market risk is reachable there
at all.

## Deliverables

the product CLI keeps its read-only query commands and gains a reduce-only write set:
reduce or remove LP, collect accrued assets, exit, turn `HOLD`/`LP`/`AUTO_SWAP` off, and
lower a USDG exposure limit. Each accepted write uses the same versioned records the Web
write path T085 produces — never a parallel store — and emits an immutable audit event
carrying actor, target, previous and new version, reason and evidence; a refused write
emits its reason code and changes nothing. The LP-side commands run through the risk
gateway, the T091 planner's pre-execution checks and the isolated signer boundary; the
permission-side commands act on an approved authorization version and fail closed when it
is stale or absent. A command that would raise a permission, raise an exposure limit,
enable a flag, increase liquidity or open a new position is refused with a pointer to the
Web entry point, and the refusal is recorded. The CLI never accepts, prompts for or echoes
a private key, Keystore password, seed or credential through an argument, an environment
variable, a file or the Web; signer unlock stays a non-echoing interactive terminal prompt.

## Acceptance

each reduce-only command reaches its intended effect and leaves one immutable audit event
with actor, previous and new version, reason and evidence (test); a command that would raise
a permission, raise an exposure limit, enable a flag, increase liquidity or open a position
is refused, changes no version and no ledger entry, and records the refusal with the Web
entry point it points to (test); a command issued against a stale, absent or superseded
authorization version fails closed (test); a reduction is accepted while an
increase-risk approval is pending, while the Web is unavailable and while a limit is already
breached (test); an LP-side command cannot bypass the risk gateway, the T091 pre-execution
checks or the signer boundary, and a plan that fails pre-execution is not submitted (test);
no command path accepts a key, password or credential from any input source (test,
`tests/test_no_signing_paths.py`).

## Must not

raise a permission, an exposure limit or market risk from the CLI; bypass Web approval for
an increase; provide a generic transaction or arbitrary-call surface; accept or echo a
private key, Keystore password, seed or credential; write to a version store other than the
one the Web write path uses; skip the risk gateway, pre-execution or the audit event; or
weaken, disable or re-implement an existing `Must not` clause of the Web write path.
