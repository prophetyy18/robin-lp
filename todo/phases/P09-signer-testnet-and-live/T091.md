# T091 — Build deterministic V4 transaction planning and preflight

> Phase: `P09`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

## Dependencies

T021, T043, T049, T070, T071, T072

## Outcome

an approved strategy intent becomes exactly one reviewable state-bound V4 plan.

The planner accepts more than one intent class. Besides an approved strategy intent, it
plans the risk-reducing intents the CLI of `CTRL-CLI-001` sends — reduce or remove LP,
collect accrued assets, exit — through the same pre-execution checks, and without
requiring a strategy approval, because they only lower a permission or an exposure. Every
intent that would raise a permission or an exposure is not planned from the CLI at all:
it goes through the Web write entry (`WEB-GLOBAL-003`, `G-PERM-WRITE-01`), which is the
only increase path.

## Deliverables

allowlisted PoolManager/periphery actions for required Swap and liquidity
lifecycle; exact calldata decoding; allowance/Permit2 plan; fixed-block simulation;
amount min/max, deadline, Hook delta, Gas, nonce and MEV/slippage bounds; idempotency key.

The intake covers both caller classes: an approved strategy intent and a CLI-issued
reduce, collect or exit intent each become exactly one plan carrying the same decoded
fields, allowance, simulation, bounds, idempotency and pre-execution checks, while a
CLI-issued intent that would raise a permission or an exposure is refused before planning,
with the reason recorded and the Web write entry named.

## Acceptance

every decoded field matches intent/authorization; stale state/code/price/
simulation rejects; replacement/reorg/restart cannot duplicate an economic action; unknown
method/target/value/calldata is unsignable; a CLI reduce, collect or exit intent issued
against a current authorization version is planned with the same decoded-field,
stale-state, idempotency and simulation checks as a strategy intent and without requiring
a strategy approval (test); and a CLI-issued intent that would raise a permission, raise
an exposure, enable a flag, add liquidity or open a position is refused before planning,
changes no state and records the pointer to the Web write entry (test).

## Must not

expose arbitrary call construction, change Range/limits, bypass T070, assume
Remove Liquidity is safe when Hook semantics changed, require a strategy approval for a
risk-reducing CLI intent, or plan a CLI-originated increase.
