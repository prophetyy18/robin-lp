# T102 — Evaluate trained models as strategy components through the event-driven engine

> Phase: `P10`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-18`

## Dependencies

T061, T101, T106

## Outcome

A trained model can be evaluated as a component of the strategy layer end to end, and
the verdict on it comes from simulated LP economics rather than from a prediction
metric. A statistically accurate model that produces worse net LP results is recorded
as a rejection, which is the whole point of the task.

The model occupies the replaceable regime and fee-opportunity interfaces the strategy
contract already defines, under a registered T068 strategy identity — registered through
the T068 registry rather than through a second registry of its own — with a parameter
schema, a version and code provenance, and a run reaches it only by naming that registered
identity through the T069 run entry point; an identity the registry does not carry is
refused rather than inferred, defaulted or substituted. It changes nothing else: no ledger,
no candidate-action semantics, no central risk check, no execution path and no audit event
format.

## Deliverables

- Model-backed implementations of the strategy layer's regime and fee-opportunity
  interfaces, consuming only versioned point-in-time inputs, returning versioned,
  unit-carrying assessments, and reachable only through the registered T068 strategy
  identity a run names, with the parameter schema, version and code provenance that
  identity declares. The schema declares the model-backed strategy's tunable parameters
  with their names, types, units and ranges; the component is never requested by its
  implementation module, by a free-text name or by an unregistered or inferred identity.
- A deterministic fallback to the rule-based baseline whenever the model artifact is
  missing, stale, unversioned or out of its training distribution, so an unavailable
  model degrades to the existing behavior rather than to an undefined one. This fallback
  covers the model artifact's availability only: it never substitutes for the registered
  identity, for a validated manifest or for the current schema-bound robustness evidence
  below.
- Walk-forward evaluation driven through the event-driven backtest engine, with
  point-in-time, machine-recorded fold boundaries, consuming T106 as the current
  schema-bound robustness and anti-overfitting protocol: every parameter-surface axis is
  built from the exact registered identity and parameter-schema revision the evaluated
  run's validated T105 manifest records, every axis name, type, unit and value is declared
  by that schema and inside its declared range, and the registry and schema identity,
  version and checksum are recorded with the surface and with the report.
- A side-by-side report of the rule baseline and the model on identical data, capital,
  costs and splits, stating the number of independent episodes and the uncertainty of
  the comparison.
- Episode-level bootstrap confidence intervals and a regime-conditional breakdown, so
  a favourable aggregate cannot hide a loss concentrated in one market state.
- An explicit rejection record naming which model improved prediction and worsened
  economics, and why.
- A fail-closed evidence boundary: missing, legacy-only or revision-mismatched T106
  robustness evidence yields `UNCERTAIN` or `NO_TRADE` for the affected configuration or
  blocks publication of the robustness conclusion, and a model-backed strategy whose
  registered identity, parameter schema or code binding is missing, unregistered or
  mismatched is not evaluated as a current strategy. Neither case falls back to the
  unrestricted `T064` predecessor robustness surface, to an inferred or default identity,
  or to an unqualified baseline.
- Legacy `T064` robustness artifacts that carry no registry or schema binding stay
  read-only, byte-identical and explicitly legacy; they are consumed only in an explicitly
  labelled compatibility analysis and never as current robustness evidence, and their
  registry, schema or revision fields are never inferred.

## Acceptance

Substituting the trained model for the rule model changes no ledger, risk, execution or
audit contract, verified by the same dependency and interface tests that protect the
rule implementation; a model that improves a prediction metric while worsening net LP
economics is reported as a rejection and never as a success; walk-forward boundaries
are point-in-time and reproducible from the manifest; an uncalibrated or
out-of-distribution model is detected and yields `UNCERTAIN` or `NO_TRADE` rather than a
forced position; insufficient capital, stale state, invalid ticks and missing data fail
before an intent is created, exactly as they do for the rule model; and the report
states the number of independent episodes, the bootstrap interval and the regime
breakdown, including for the losing and rejected configurations.

The walk-forward evaluation of a model-backed strategy resolves the evaluated run's
validated T105 manifest and the schema-bound T106 surface, records the same registry and
schema identity, version and checksum as that manifest, and is deterministic across
repeated construction (test); the same evaluation runs positively over at least two
heterogeneous registered T068 strategy identities whose declared parameter schemas differ
in axis names, types, units or ranges, each built from its own evaluated run's validated
T105 manifest and its own registered schema revision, each surface recording the registry
and schema identity, version and checksum it was built from, deterministic per schema
under repeated construction, and a point one of the two schemas declares is still refused
for the schema that does not declare it (test, fixture); a point the registered schema
does not declare, an out-of-range, wrong-unit or wrong-type point, and a schema revision
that disagrees with the evaluated run's manifest are rejected before any fold is
evaluated (test); missing,
legacy-only or mismatched T106 evidence yields `UNCERTAIN` or `NO_TRADE` or blocks
publication rather than falling back to the unrestricted `T064` predecessor surface (test);
a model-backed strategy identity the registry does not carry, and a run request that does
not name a registered identity, are refused rather than evaluated under an inferred or
default identity (test); a migration fixture keeps a legacy `T064` robustness artifact
byte-identical and labelled legacy, incompatible registry or schema revisions are never
merged into one sensitivity conclusion, and the artifact cannot be consumed as current
robustness evidence (fixture, test); and an old-path-unreachable test proves current
evaluation cannot construct a parameter surface through the unrestricted `T064` builder
(test).

Boundary and failure cases covered: a model artifact trained on a pool set disjoint
from the evaluation pool; a model whose inputs are present but entirely stale; a model
whose predictions are constant; a walk-forward fold shorter than one episode; an
evaluation period in which the model never trades; a registered strategy whose T106 surface
is missing or comes from an incompatible schema revision; and a legacy robustness artifact
offered as current evaluation evidence.

## Must not

Let a model emit a position, a size or a tick range directly; bypass, weaken or
duplicate the central risk gateway (`T070`); let a model become the live default or
acquire any execution authority, or let model or robustness evidence grant execution,
approval or promotion authority; retune on the evaluation period; drop a losing pool,
regime or fold from the comparison; fall back to the unrestricted `T064` predecessor
robustness surface or to an unqualified baseline when the current schema-bound evidence is
missing, legacy or mismatched; treat a legacy `T064` robustness artifact, or an
unregistered, inferred or default identity, as current evidence; or report model
diagnostics in place of simulated LP economics.
