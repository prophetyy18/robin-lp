# T102 — Evaluate trained models as strategy components through the event-driven engine

> Phase: `P10`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-18`

## Dependencies

T061, T101

## Outcome

A trained model can be evaluated as a component of the strategy layer end to end, and
the verdict on it comes from simulated LP economics rather than from a prediction
metric. A statistically accurate model that produces worse net LP results is recorded
as a rejection, which is the whole point of the task.

The model occupies the replaceable regime and fee-opportunity interfaces the strategy
contract already defines, and changes nothing else: no ledger, no candidate-action
semantics, no central risk check, no execution path and no audit event format.

## Deliverables

- Model-backed implementations of the strategy layer's regime and fee-opportunity
  interfaces, consuming only versioned point-in-time inputs and returning versioned,
  unit-carrying assessments.
- A deterministic fallback to the rule-based baseline whenever the model artifact is
  missing, stale, unversioned or out of its training distribution, so an unavailable
  model degrades to the existing behavior rather than to an undefined one.
- Walk-forward evaluation driven through the event-driven backtest engine, with
  point-in-time, machine-recorded fold boundaries.
- A side-by-side report of the rule baseline and the model on identical data, capital,
  costs and splits, stating the number of independent episodes and the uncertainty of
  the comparison.
- Episode-level bootstrap confidence intervals and a regime-conditional breakdown, so
  a favourable aggregate cannot hide a loss concentrated in one market state.
- An explicit rejection record naming which model improved prediction and worsened
  economics, and why.

## Acceptance

Substituting the trained model for the rule model changes no ledger, risk, execution or
audit contract, verified by the same dependency and interface tests that protect the
rule implementation; a model that improves a prediction metric while worsening net LP
economics is reported as a rejection and never as a success; walk-forward boundaries
are point-in-time and reproducible from the manifest; an uncalibrated or
out-of-distribution model is detected and yields `UNCERTAIN` or `NO_TRADE` rather than a
forced position; insufficient capital, stale state, invalid ticks and missing data fail
before an intent is created, exactly as they do for the rule model; and the report
states the number of independent episodes, the bootstrap interval and the regime
breakdown, including for the losing and rejected configurations.

Boundary and failure cases covered: a model artifact trained on a pool set disjoint
from the evaluation pool; a model whose inputs are present but entirely stale; a model
whose predictions are constant; a walk-forward fold shorter than one episode; and an
evaluation period in which the model never trades.

## Must not

Let a model emit a position, a size or a tick range directly; bypass, weaken or
duplicate the central risk gateway; let a model become the live default or acquire any
execution authority; retune on the evaluation period; drop a losing pool, regime or
fold from the comparison; or report model diagnostics in place of simulated LP
economics.
