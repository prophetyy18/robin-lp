# T103 — Build the research console

> Phase: `P10`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-18`

## Dependencies

T085, T102, T109

## Outcome

The owner can select research data visually, inspect what a replayed pool state and a
hypothetical position actually did, assemble train, validation and test datasets with
both pool and time selection, run and inspect models, and read results broken down by
market regime and time slice — without developer tools and without reading files.

This task owns the four research pages added to the console specification:
`WEB-PAGE-008` data coverage and downloads, `WEB-PAGE-009` replay and position
inspector, `WEB-PAGE-010` dataset builder, and `WEB-PAGE-011` model laboratory. The
pages owned by the earlier console tasks keep their own acceptance; this task neither
reimplements them nor weakens them.

## Deliverables

- `WEB-PAGE-008` — a coverage calendar driven by the measured per-pool datasets, showing
  available and missing ranges against volume, realized volatility, swap activity and
  liquidity, so a period can be chosen from evidence rather than from a date guess.
- `WEB-PAGE-009` — a market-only replay inspector that consumes T109's dataset-addressed
  `MarketState(dataset_version, pool_key_id, cursor)`: post-event reconstructed pool state at a
  chosen `MarketCursor`, the tick liquidity distribution around the current price, and the swaps
  that moved it. A block-only choice means end-of-block and a pre-first-event choice returns the
  recorded initial market state. The position overlay is separately and prominently labelled
  **hypothetical**; its range, inventory, accrued fees and PnL are an analysis of that selected
  market path, never `RunState`, saved simulation evidence or T088's exact completed-run replay.
  T104 is the sole source of fee-growth and exact range-fee values for the overlay, and each value
  carries T104's dataset/window/reconstruction provenance beside it. The page binds the dataset
  content hash, PoolKey, range, cursor and reconstruction revision and fails closed on mismatch;
  it creates no second market replay or fee projection.
- `WEB-PAGE-010` — a dataset builder: pool and block-range selection with segment roles
  for train, validation, test and backtest, pool holdout and time holdout as explicit
  choices rather than incidental ones, a visible coverage and qualification summary, and
  saved reproducible dataset definitions carrying their version.
- `WEB-PAGE-011` — a model laboratory: training and evaluation runs against a chosen
  dataset version, feature importance, probability calibration and quantile coverage,
  the rule-baseline comparison, and the rejection record for models that did not survive
  the economic evaluation.
- A results view inside `WEB-PAGE-011` that breaks performance down by regime and time
  slice and shows the episode-level uncertainty interval, not only an aggregate. This view
  is not the backtest result page the specification names: `WEB-PAGE-013` is a different
  surface, owned by T088, and this task neither implements it, substitutes for it, nor
  presents its own view as it.
- Every training or evaluation trigger the model laboratory offers submits through the
  T109 run entry point and carries that entry point's run identity and lifecycle semantics
  — identity, queued and running with progress, failed, cancelled and succeeded with a
  reason code, and no complete-looking artifact after a cancellation or a failure —
  instead of implying a second run surface with its own identity or state, and the page
  displays the run state that entry point reports rather than restating it.
- Explicit empty, partial, conflicting, stale and unavailable states on every page, and
  a `RELATIVE_ONLY` dataset that displays relative results rather than a fabricated USD
  number.

## Acceptance

Every page this task owns maps to component and API tests; the coverage view is derived
from the measured dataset and a range with no data is shown as absent rather than
interpolated or blank; dataset definitions save and reproduce, and re-opening a saved
definition yields the same pools, ranges and segment roles; a pool below `backtest`
support level cannot be added to a dataset from the interface; model diagnostics and the
economic verdict are shown together so a good prediction score cannot be read as a good
strategy; regime and time-slice results expose the number of episodes behind each slice;
a `RELATIVE_ONLY` dataset is visibly distinguished from a USD-denominated one; no page
can be reached in a way that mutates domain state from a read path; the results view this
task renders is not the `WEB-PAGE-013` backtest result page T088 owns and is not
presented, linked or labelled as it (test); `WEB-PAGE-009` returns T109 `MarketState` without a
strategy for pre-first-event, exact intra-block and block-only/end-of-block cursors and equals
direct T040/T041 prefix reconstruction (test); its position overlay is always labelled
hypothetical and is never represented as `RunState`, `ReplayFrame` or exact run evidence (test);
every fee/range-fee value equals the direct T104 query and displays matching dataset/window/
reconstruction provenance, while inspection proves neither this page nor T109 contains a second
fee implementation (test); dataset hash, PoolKey, cursor/range and revision mismatches fail closed,
and architecture tests prove no ad hoc or second replay path is reachable (test); and a training or evaluation trigger submits
through the T109 entry point and displays the same run identity, status, progress, failure
reason and cancellation result that entry point reports, with no second run identity and
no second run-state store (test).

Boundary and failure cases covered: a dataset whose coverage is partly missing; a replay
window in which the position never enters range; a model whose training dataset was
later superseded; a dataset definition referencing a pool that has since been demoted;
and a console session whose background service is unavailable.

## Must not

Fetch or display private material, credentials or secrets; mutate domain state from a
read model; hide a failed, losing or rejected result; let a dataset or model definition
become an execution approval or appear in an execution-shaped control; treat console
availability as strategy availability; or present an interpolated, partial or
synthetic series as measured coverage; present a hypothetical position as an exact completed-run
state; invoke strategy code to obtain market state; construct a second replay path; replace or
duplicate T104; or return a market/fee value whose dataset, pool, cursor or provenance binding
does not validate.
