# T103 — Build the research console

> Phase: `P10`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-18`

## Dependencies

T085, T102

## Outcome

The owner can select research data visually, inspect what a replayed pool state and a
hypothetical position actually did, assemble train, validation and test datasets with
both pool and time selection, run and inspect models, and read results broken down by
market regime and time slice — without developer tools and without reading files.

This task owns the four research pages added to the console specification:
`WEB-PAGE-008` data coverage and downloads, `WEB-PAGE-009` replay and position
inspector, `WEB-PAGE-010` dataset builder, and `WEB-PAGE-011` model laboratory. The
pages owned by the earlier console tasks keep their own acceptance; this task neither
reimplements them nor weakens them.

## Deliverables

- `WEB-PAGE-008` — a coverage calendar driven by the measured per-pool datasets, showing
  available and missing ranges against volume, realized volatility, swap activity and
  liquidity, so a period can be chosen from evidence rather than from a date guess.
- `WEB-PAGE-009` — a replay inspector: reconstructed pool state at a chosen block, the
  tick liquidity distribution around the current price, the swaps that moved it, and a
  hypothetical position's range, inventory, accrued fees and PnL over the selected
  window.
- `WEB-PAGE-010` — a dataset builder: pool and block-range selection with segment roles
  for train, validation, test and backtest, pool holdout and time holdout as explicit
  choices rather than incidental ones, a visible coverage and qualification summary, and
  saved reproducible dataset definitions carrying their version.
- `WEB-PAGE-011` — a model laboratory: training and evaluation runs against a chosen
  dataset version, feature importance, probability calibration and quantile coverage,
  the rule-baseline comparison, and the rejection record for models that did not survive
  the economic evaluation.
- A results view that breaks performance down by regime and time slice and shows the
  episode-level uncertainty interval, not only an aggregate.
- Explicit empty, partial, conflicting, stale and unavailable states on every page, and
  a `RELATIVE_ONLY` dataset that displays relative results rather than a fabricated USD
  number.

## Acceptance

Every page this task owns maps to component and API tests; the coverage view is derived
from the measured dataset and a range with no data is shown as absent rather than
interpolated or blank; dataset definitions save and reproduce, and re-opening a saved
definition yields the same pools, ranges and segment roles; a pool below `backtest`
support level cannot be added to a dataset from the interface; model diagnostics and the
economic verdict are shown together so a good prediction score cannot be read as a good
strategy; regime and time-slice results expose the number of episodes behind each slice;
a `RELATIVE_ONLY` dataset is visibly distinguished from a USD-denominated one; and no page
can be reached in a way that mutates domain state from a read path.

Boundary and failure cases covered: a dataset whose coverage is partly missing; a replay
window in which the position never enters range; a model whose training dataset was
later superseded; a dataset definition referencing a pool that has since been demoted;
and a console session whose background service is unavailable.

## Must not

Fetch or display private material, credentials or secrets; mutate domain state from a
read model; hide a failed, losing or rejected result; let a dataset or model definition
become an execution approval or appear in an execution-shaped control; treat console
availability as strategy availability; or present an interpolated, partial or
synthetic series as measured coverage.
