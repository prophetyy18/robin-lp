# T085 — Implement versioned Web approval and safety controls

> Phase: `P08`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

## Dependencies

T070, T081, T084

## Research definitions in the write path

Research dataset and model definitions are versioned through this task's write path —
draft, impact preview, reauthentication, confirmation, immutable version and audit
event — like any other versioned object, so their content, actor and reason are
recorded. That write path is a research and configuration path: such a definition is
never an execution approval, never appears or is labelled as one, and must not be
reachable from an execution-shaped control (ADR-014). Saving one grants no permission,
weakens no limit and changes no active strategy, pool or authorization.

## Outcome

every risk-changing user action is explicit, versioned and auditable while
reduce-only controls remain available.

## Deliverables

draft → impact preview → reauthentication → confirmation workflows
for target token, PoolKey, strategy, permissions, USDG/Gas/risk limits, pause/takeover,
reduce/exit and promotion; the same versioned write path for research dataset and model
definitions, recorded as research artifacts; CSRF/session/optimistic-concurrency/
idempotency controls.

## Acceptance

stale tabs, replay, duplicate submit, expired session and conflicting
versions fail closed; increases invalidate affected authorization; reductions do not
silently liquidate; every accepted/rejected write has actor/version/reason/evidence; a
saved dataset or model definition cannot be read as, converted into, or offered as an
execution approval, and no execution-shaped control can create, promote or reference
one.

## Must not

accept a private key/Keystore password, expose a generic transaction form,
let CLI bypass approval, or infer consent from viewing/alert acknowledgement; or let a
dataset or model definition become an execution approval, appear as one, or be
reachable from an execution-shaped control.
