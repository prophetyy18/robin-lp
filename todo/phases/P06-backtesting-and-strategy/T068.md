# T068 — Register strategy identities with their parameter schema and code provenance

> Phase: `P06`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-20`

## Dependencies

T060, T062, T063, T065

## Outcome

every strategy a run can execute has one registered identity — parameter schema, version
and code provenance — and a manifest records that identity, so the T065 adaptive-Range
strategy is named instead of being absent from a closed five-name vocabulary.

## Deliverables

a strategy registry, in the strategy layer of `ARCHITECTURE.md` §2.2, that enumerates
every strategy a backtest or paper run may execute and carries for each one a stable
identity string, a parameter schema (parameter names, types, units and allowed ranges),
a version, and code provenance: the module that implements it and the code revision that
module was built from. Registration covers the T062 baselines and the T065 adaptive-Range
strategy, which no manifest identity names today.

The manifest's `strategy_kind` validation reads its allowed identities from the registry
instead of a hard-coded five-name set, still rejects an identity the registry does not
carry, and rejects a manifest whose `strategy_params` the registered schema does not
declare, so a run cannot be published with parameters its strategy does not accept.
Registry enumeration and its checksum are deterministic, and the registry is readable
without a network call, without the Web entry point and without reading a strategy's
implementation.

## Acceptance

the T065 adaptive-Range strategy is selectable by its registered identity and a manifest
produced through the T063 path records that identity (test); a manifest whose
`strategy_kind` is absent from the registry, and a manifest whose `strategy_params` the
registered schema rejects, both fail validation instead of publishing (test); two
enumerations over the same revision return the same order and the same registry checksum,
and every registered identity's code provenance resolves to a module that exists (test);
the layer check passes with no new suppression: `python -m tools.check_imports check`
reports no finding for the registry module, and the registry imports neither the RPC
adapter, storage, the signer, nor the Web entry point (test).

## Must not

accept an unregistered or caller-invented strategy identity, replace a closed definition
with "whatever the caller supplies", weaken the validation the manifest already applies to
the identities it carries today, register a strategy by symbol or display name rather than
by identity, or import RPC, storage, signing or presentation code.
