# T067 — Write the strategy authoring guide

> Phase: `P06`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-19`

## Dependencies

T060, T061

## Outcome

an author who has only this repository can write a strategy the event-driven backtest engine
actually runs, and can check it before asking for review, because the callback the engine consults,
what it may know, what it must return, what the layer forbids and how to run the result are written
down next to the code, the specification and the contracts that already say them.

## Deliverables

1. `docs/implement/strategy/AUTHORING_GUIDE.md`, a guide for an author with no other context,
   covering:
   - the callback shape the engine consults and when it is consulted: the request the engine hands
     the callback, the response it must return, the decision kinds (`NO_TRADE`, `WAIT`, `PROPOSE`)
     and what the engine does with each, and at which point of the event clock a decision is asked
     for — taken from the engine and the contracts, not from this guide's own reading;
   - the field semantics and units of what the callback receives and returns: what every field
     means, which quantities are integers or fixed-point and in which scale, which carry chain,
     pool, block or time identity and which are unitless, and which of them are point-in-time
     values;
   - the fill and information-frontier assumptions a strategy may rely on: that the callback sees
     only the observations visible at its decision time and in the order the engine presents them,
     that fills, latency, costs and failures are the engine's and not the strategy's, and what each
     assumption forbids an author from assuming;
   - the prohibitions the strategy layer carries: no RPC, storage, signing or execution access, no
     ledger or state mutation, no wall clock or unseeded randomness, no future observation, no
     model that emits a position or bypasses the risk gateway, and the naming rule that a component
     name never denotes an output and an output name never denotes a component;
   - a self-check an author can run before asking for review: the example of deliverable 2, the
     exact commands that run it through the committed engine on committed fixtures, and what a
     correct run and a rejected run each look like.
2. A complete, minimal example strategy committed at
   `docs/implement/strategy/example_strategy.py`, outside `src/robinhood_lp/`, that uses only the
   documented callback and the declared contracts, and that the guide shows in full. The committed
   example is the source of truth for the code it shows: the guide's quoted block and the committed
   example must agree.
3. Every normative statement in the guide cites its source — `docs/spec/strategy/STRATEGY_ECONOMICS.md`
   §7, the ADRs it rests on, and the task contracts `T060`, `T061`, `T062` and `T065` — and the
   guide states that the cited source wins where the guide and its source disagree, so it explains
   the boundary instead of becoming a second authority for it. It is written against the interface
   the specification now states, including that the adapter between the engine callback and the
   strategy layer's components is owned by `T065` and is not delivered by this task.
4. A committed test that loads the example, runs it through the committed engine on committed
   fixtures with the commands the guide documents, and asserts the expected decisions or audit
   outcome, plus a committed assertion that the guide's quoted example block still matches
   `docs/implement/strategy/example_strategy.py`; a guide whose commands, imports or callback shape
   have gone stale therefore fails the suite instead of misleading the next author.

## Acceptance

`docs/implement/strategy/AUTHORING_GUIDE.md` exists and contains all five content blocks of
deliverable 1; the example exists at the declared path, is complete, and runs through the committed
engine on committed fixtures under the guide's own commands, with the committed test proving it and
failing when the guide's block or the documented commands drift from it; every normative statement
in the guide carries a citation that resolves to the document or contract it names, and the guide
defers to that source rather than restating it as its own authority; the guide names `T065` as the
adapter owner and describes the engine callback as the boundary a backtest actually crosses today,
as `docs/spec/strategy/STRATEGY_ECONOMICS.md` §7 now states; the guide cites nothing retired as
current — the ten-million-block window is not the research range, and a superseded task is not
named as a live owner; no credential, `.env` value, key material or endpoint credential appears in
the guide or the example; `pytest`, `ruff check`, `ruff format --check` and `mypy src tests` pass.

## Must not

state a specification clause or a contract obligation as the guide's own authority, or introduce a
rule no cited source states; add a module under `src/robinhood_lp/` — every module there needs a
layer from the layer map and this task adds none — or make the example part of the product path;
change the engine, the strategy contracts, `docs/spec/`, a task contract or `todo/config.yaml`: a
guide that finds a contradiction reports it and routes it instead of patching it; present the
example as a profitable, approved or live strategy, or let it acquire execution authority; add a
third-party dependency or a network read; weaken an existing CI job, test or assertion.
