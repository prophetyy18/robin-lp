# T069 — Deliver the product-level backtest run entry point

> Phase: `P06`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-20`

## Dependencies

T041, T053, T061, T068, T105

## Outcome

one product-level entry point turns a registered strategy, its parameters, a data range
and the run assumptions into a reproducible experiment manifest and report, with status,
progress, failure and cancellation observable, and with no Web session required to run it.

## Deliverables

a run request naming the dataset version, the registered strategy identity and its
parameters, the pool and block range, and the seed, fill, cost and quote assumptions the
T105 manifest records; orchestration that joins stored partitions, replay, features, the
engine and the manifest into one run without defining any of them a second time, publishing
the T105 registry-bound manifest and reports; a run state surface covering queued, running
with progress, failed, cancelled and succeeded, durable across a process restart and
carrying a reason code for every failure and cancellation; cancellation that stops a run
without publishing a partial or complete-looking result; and a documented command that
starts, lists, observes and cancels a run with no Web process running.

T069 alone owns the durable product-run lifecycle: run identity, queue, progress, status,
failure, cancellation and restart. The T105 artifact rerun remains an artifact operation
that verifies and deterministically reproduces an already saved manifest, and it acquires
no T069 run state; a rerun becomes a product run only when it is invoked through a new T069
run record. A rerun requested through the product path creates a new durable run linked to
the source manifest, with the source manifest preserved read-only and never mutated, under
the same status, progress, cancellation, failure and restart semantics as any other run.

## Acceptance

a new run request naming the dataset version, the registered strategy identity and its
parameters, the pool and block range, and the seed, fill, cost and quote assumptions publishes
exactly the registry-bound manifest and reports the T105 contract defines, with one RunRequest
carrying exactly one pool_key_id and publishing exactly one manifest under the request's own
run_id (test, golden); two new run requests over two heterogeneous pool fixtures that share
dataset_version, reporting_numeraire and valuation_qualification each publish exactly one
manifest under their own run_id, and the shared dataset_version, reporting_numeraire and
valuation_qualification are recorded on every published manifest under its own run_id (test);
re-running the same request reproduces byte-equivalent canonical artifacts
(test); a product rerun creates a new durable run record linked to the source manifest and
leaves that source manifest byte-identical, while the artifact rerun command stays an
artifact operation carrying no T069 run state (test); a cancelled run and a failed run
publish no manifest and no report, and a restart while a run is in progress neither
duplicates the run nor loses its state (test); a request naming an unregistered strategy
identity, a missing dataset version, a legacy pre-registry manifest as its source, or a
range outside the dataset's own coverage fails closed before any result is written and
records its reason (test); every command starts, observes and cancels a run while no Web
process is running (test).

## Must not

mutate stored partitions, approvals, risk configuration or the strategy registry; publish
a result without its manifest and coverage; overwrite or mutate the source manifest of a
linked rerun; create a second engine, manifest or feature implementation beside the ones
T061, T105 and T050–T053 own; absorb the T105 artifact rerun into the product path or give
it T069 run state; accept a legacy or unregistered input as a current run; keep run state
only in memory; write a credential, endpoint alias or key material into the run record; or
make a Web session necessary to start, observe, cancel or reproduce a run.
