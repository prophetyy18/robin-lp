# T108 — Update the strategy authoring guide for registered identity

> Phase: `P06`
> Contract status: `OWNER_AMENDMENT_A0014`

## Dependencies

T067, T068, T105

## Outcome

an author can implement and check a strategy through the real engine callback while understanding
that only its registered identity, schema, version and code provenance authorize it for a run.

## Deliverables

Update `docs/implement/strategy/AUTHORING_GUIDE.md`,
`docs/implement/strategy/example_strategy.py` and their drift tests while preserving every valid
T067 obligation: callback timing and shapes; request/response fields, units and point-in-time
semantics; `NO_TRADE`, `WAIT` and `PROPOSE`; engine-owned fills, latency, costs and failures; no RPC,
storage, signing, execution, ledger mutation, wall clock, unseeded randomness, future observation,
position-emitting model or risk bypass; the T065 adapter boundary; a complete minimal non-product
example; exact runnable commands; positive and rejected outcomes; source citations; and matching
quoted/example code.

Teach the T068 registry as the sole current authority for strategy identity. Document how an author
selects a stable identity, defines the typed/unit-bearing/range-bounded parameter schema, increments
the strategy/schema version, records code provenance and obtains a registry-bound T105 manifest.
Explain that callback `notes`, labels, display names, symbols and other free text are descriptive
and non-authoritative: they cannot identify, register, substitute or approve a strategy. Update the
example to carry or be invoked through a registered identity and schema without moving it into the
product package, and add drift tests that fail if the guide/example again presents free text or a
hard-coded name set as identity authority.

## Replacement and migration

- **Old code reachability:** replace the current guide/example as the current authoring entry point
  and update `tests/test_authoring_guide_t067.py` or a successor test. Remove or correct current
  instructions that make `notes` identify policy. Historical Git versions remain available, but no
  current README, guide link or generated documentation may route authors to the old semantics.
- **Historical data and artifacts:** documentation and example have no mutable production data.
  Preserve prior guide/example/review evidence in Git history; existing manifests remain governed
  by T105's legacy rules and are not rewritten because the guide changed.
- **Runtime cutover and rollback/fail closed:** the example remains documentation-only and gains no
  runtime authority. If the registered example cannot validate through T068/T105, its documented
  current run command must fail and the guide must not offer a free-text fallback. Rollback restores
  the last registry-correct guide or withdraws the command rather than restoring old identity text.
- **Downstream dependencies:** T067 has no ordinary `PLANNED` direct consumer in the task graph.
  Future authoring references must cite T108 as current and may cite T067 only as immutable history.
- **Security:** retain the ban on network reads, dependencies, credentials, `.env` values, key
  material and execution authority. Registration is identity metadata, not permission to trade.
- **Verification:** retain T067's runnable-example, rejected-run, quote-drift, citation, formatter,
  lint, type and full-suite checks; add positive registered-identity/schema/manifest coverage,
  negative free-text/unregistered/out-of-schema cases, compatibility assertions for preserved
  callback behavior, and old-path-unreachable checks over current guide links and commands.

## Acceptance

The guide contains all T067 content blocks and cites every normative rule to current sources,
including T068 and T105. Its complete example and quoted block agree, run through the committed
engine on committed fixtures and demonstrate a registered identity plus validated schema. Tests
fail for unregistered identity, invalid parameters, free-text identity substitution, stale quoted
code and current links/commands that reach the old guide semantics. The example remains outside
`src/robinhood_lp/`, has no network or execution authority, and no secret appears.

## Must not

make the guide a second authority, introduce an uncited rule, add a product module or third-party
dependency, change the engine or governing Spec, present the example as profitable/approved/live,
treat notes/display names/symbols as identity, infer a registry entry, weaken CI, or rewrite
historical manifests or evidence.
