# T109 — Preserve exact historical market and strategy-run replay

> Phase: `P06`
> Contract status: `OWNER_AMENDMENT_A0022`

## Dependencies

T041, T052, T061, T069, T100, T105

## Outcome

the product can read canonical historical market state at a supported cursor and can replay the
exact strategy, position and accounting state of one successful historical simulation at that
same cursor without rerunning strategy code or duplicating the market timeline.

## Deliverables

Define one canonical `MarketCursor` ordered as `(block_number, transaction_index, log_index)`, with
a block-only request meaning end-of-block, and a dataset-addressed
`MarketState(dataset_version, pool_key_id, cursor)` read contract. It resolves T100's immutable
partition references and composes T040/T041 reconstruction; any persisted reconstruction
checkpoint is only a sparse, checksummed projection bound to the dataset content hash and
reconstruction revision, never a second source of market truth.

Extend the successful T069 publication transaction with an immutable, versioned and checksummed
simulation-evidence artifact bound to the run, dataset content hash, PoolKey, selected range,
registered strategy identity, and engine, accounting and evidence-schema revisions. The artifact
contains the ordered run-specific facts needed to recover decisions and lifecycle transitions,
position range and liquidity, token0/token1 integer inventory, fee and cost accounting, equity,
drawdown and T052 attribution at a cursor. It may combine sparse complete run-state checkpoints
with deterministic intervening transitions; it need not and must not contain a complete market
event copy or a complete run snapshot at every cursor.

Define `RunState(run_id, cursor)` as a projection from that saved evidence through the existing
T061 engine/accounting state semantics, without invoking strategy callbacks, and define
`ReplayFrame(run_id, cursor)` as a read-time composition of the run's dataset-bound `MarketState`
and same-cursor `RunState`. Validate dataset, pool, range, cursor, revision and checksum bindings
before returning a frame. This task succeeds T069 as the one product-run lifecycle and T105 as the
one manifest/report authority, integrates their publication with replay evidence, and creates no
second run, manifest, replay, backtest, strategy or accounting authority.

Preserve and take over every T069 product-run obligation: registered strategy and schema-bound
parameters, immutable dataset/pool/range and run assumptions, one durable run identity, queue,
progress, status, named failure/cancellation reasons, restart recovery, CLI start/list/observe/
cancel without a Web session, atomic successful publication, and linked product reruns that never
mutate their source manifest. T105's `rerun-manifest` remains a stateless artifact operation and
does not acquire product-run lifecycle state.

Preserve and take over every T105 obligation: registry/schema/code-bound strategy identity and
validated parameters; dataset, PoolKey, range, units, assumptions and revision provenance;
canonical manifest/report/checksum validation; per-pool publication; `RELATIVE_ONLY` handling;
historical T063 compatibility; tamper rejection; and deterministic artifact rerun. For new writes,
replace the embedded complete `input_event_list` with the immutable T100 dataset content hash and
partition references needed to resolve the same canonical input. Artifact rerun reads that pinned
dataset version and fails closed if it cannot reproduce the referenced bytes; it never calls a
current strategy merely to reconstruct an old run state.

Document compatibility explicitly: historical runs created before this evidence schema remain
byte-identical and readable as final reports but report exact historical `RunState` as unavailable;
they are not silently regenerated, upgraded or presented as replayable. Failed and cancelled runs
publish neither a complete-looking result nor complete simulation evidence. New successful runs
publish manifest, report and simulation evidence atomically, or publish none of them as successful.

## Replacement and migration

- **Old code reachability:** replace T069 as the current product-run entry point and T105 as the
  current manifest/report publisher while adapting their existing paths rather than creating a
  parallel runner or publisher. After cutover, every new product run reaches the T061 engine and
  the registry-bound publication through T109; no CLI, Web, background or test helper may publish
  a current successful predecessor-format run without the required evidence. Artifact rerun
  remains separate and stateless.
- **Historical data and artifacts:** preserve all T069 run records and T105 manifests/reports
  byte-for-byte and read-only. Pre-evidence successful runs retain their terminal result and are
  explicitly not replayable; they are never regenerated with current strategy code. New evidence
  references T100 partitions and never embeds the complete market event timeline. If T105's current
  serialization duplicates those events, migrate new writes to immutable dataset references while
  retaining a versioned legacy reader and source checksums for old artifacts.
- **Runtime cutover and rollback/fail closed:** cut over the run entry and successful publication
  atomically. A deployment that cannot write or validate evidence disables successful publication;
  rollback restores the last evidence-capable release or makes new runs unavailable, never the
  predecessor's complete-looking success path. Queued/running records survive restart and cutover
  without duplication.
- **Downstream dependencies:** later CONTRACT amendments must replace T069 or T105 with T109 in
  every ordinary `PLANNED` consumer. T073 and T084 consume current provenance, T107 and T108 consume
  the current manifest authority, T087 uses the retained lifecycle and links successful runs to
  replay, T088 consumes `ReplayFrame`, T103 consumes market-only `MarketState`, and T096 carries
  T109 evidence into the final matrix. Approved historical consumers remain immutable evidence and
  reach the preserved semantics through this successor rather than a second path.
- **Security:** evidence and read contracts grant no strategy, risk, approval, signer, execution or
  live authority and contain no credentials, endpoint secrets or key material. Existing console
  authentication and data-support gates remain unchanged.
- **Verification:** retain every T069 lifecycle, restart, cancellation, failure, CLI, registry,
  dataset-range, linked-rerun and atomic-publication test and every T105 identity, schema,
  provenance, checksum, compatibility, tamper and artifact-rerun test, then add the market/run/frame,
  legacy, no-strategy-callback, dataset-reference/no-market-copy and both predecessor-success-path-
  unreachable tests below.

## Acceptance

For two heterogeneous pool fixtures, `MarketState` at beginning, intra-block, end-of-block and
range-end cursors equals direct T040/T041 prefix reconstruction and is identical when two runs
reference the same dataset (test, golden); querying market state requires no strategy and stores no
per-run market-event copy (test). For each fixture, a successful run's projected state at entry,
in-range fee accrual, out-of-range wait, rebalance and exit cursors exactly equals the original
T061 position, integer inventory, ledger, equity and T052 attribution state captured during that
run, and repeated reads are byte-equivalent (test, golden).

Change or remove the installed strategy implementation after a run, then prove `RunState` and
`ReplayFrame` remain byte-equivalent and no strategy callback is reached (test). Prove sparse
checkpoint plus transition replay yields the same state as the original run without requiring a
snapshot per cursor (test). A missing or mismatched dataset hash, PoolKey, cursor/range, revision,
transition, checkpoint or checksum fails closed with a named reason; a pre-evidence historical run
returns an explicit unsupported/unavailable result; and failed, cancelled or atomically incomplete
runs cannot produce a replay frame (tests). No current query path calls a second replay/backtest/
accounting implementation, and storage inspection proves one canonical market-event timeline is
shared by multiple runs (architecture and integration tests).

## Must not

rerun current or historical strategy code to replay a completed run; duplicate the complete market
event timeline in simulation evidence; create a second replay, backtest, accounting, manifest or
run-lifecycle implementation; infer missing evidence from a final summary or checksum; require a
full snapshot at every cursor; mutate a published dataset, manifest, report, historical run or
legacy artifact; use current chain state, interpolation or a later checkpoint as historical truth;
publish partial evidence as a successful result; grant any execution, approval, risk or live
authority; or serialize credentials, endpoint secrets or key material.
