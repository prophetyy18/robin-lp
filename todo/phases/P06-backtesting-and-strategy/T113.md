# T113 — Expose the backtest application contract and wire the approved T112 path

> Phase: `P06`
> Contract status: `OWNER_PLAN_EXTENSION_A0046`

## Dependencies

T006, T007, T031, T040, T041, T050, T061, T100, T112

## Outcome

The product backtest has one stable, documented in-process application API. The CLI composes
that API with the real T100 dataset/partition readers and the existing T040/T041 replay, T050
features, T061 engine, and approved T112 manifest/evidence authority. The current CLI entry
uses that API; the old T109 writer is not reachable from CLI start or resume.

## Deliverables

1. Add the public backtest use-case boundary identified in ARCHITECTURE.md §2.2, with typed
   request, result, and failure types. Define adapter ports at dependency-safe locations under
   ADR-006; do not use `Any` or arbitrary callables as public contract types. Export only the
   supported application operations.
2. Add concrete composition for the existing T100 dataset and qualified partition readers,
   existing T040/T041 replay and T050 point-in-time feature path, and the T112 run/evidence
   publisher. Keep the application layer as the composition root; providers do not import one
   another. Reuse the existing replay, engine, accounting, fee, and T112 publication authorities.
3. Route CLI backtest `start` and `resume` through the application API. Do not implement or
   rewire Web page consumers owned by T087 or T103; their contracts must be amended to consume
   this supported API before those tasks activate. A missing registry, unresolved or unqualified
   partition, empty input, replay/feature failure, or cancelled run fails closed and cannot
   publish a successful current artifact. The CLI must not fall back to the predecessor T109
   writer.
4. Add an implementation guide for this public API and contract-conformance coverage for its
   providers and CLI consumers, including two heterogeneous pool fixtures and named normal,
   boundary, invalid-input, and failure cases.
5. Prove the transition preserves byte-identical historical T069/T105/T109 artifacts and
   versioned read-only legacy readers.

## Acceptance

- The public import path mapped by ARCHITECTURE.md §2.2 is described in the implementation guide;
  the API contract follows `COMPONENT_CONTRACTS.md`; requests, results, error codes, units,
  event-time semantics, cancellation, side effects, and compatibility behavior agree across Spec,
  types, and tests.
- Two heterogeneous pool fixtures traverse the current product entry from registered T100
  partition references through the actual T040/T041 replay and T050 point-in-time feature path
  into T061, and publish only paired T112-versioned artifacts. A test traces a non-empty source
  event at its availability cursor.
- CLI `start` and `resume` invoke the application API. Inspection and negative tests prove no
  current CLI path reaches `BacktestOrchestrator`'s T109 writer, fabricates partition refs, skips
  replay/features, or succeeds with an empty/unqualified source. Each failure has a named reason
  and publishes no successful manifest or evidence.
- Provider conformance checks prove the storage, partition-resolution, replay/feature, and
  publication adapters obey the same typed contracts. Invalid identity, hash, pool, range,
  schema, cursor, and version bindings fail closed.
- Existing T112 manifest/evidence bytes and all historical T069/T105/T109 artifacts remain
  unchanged and readable only through their declared versioned readers. The transition adds no
  second replay, accounting, fee, risk, execution, signer, or publication authority.
- Public module and package imports remain within the ADR-006 dependency graph; the import-graph
  check, repository quality gates, and all task-specific checks pass.

## Must not

Create a second replay, feature, backtest, accounting, fee, manifest, evidence, risk, execution,
signer, or publication authority; expose adapter internals as the public application API; use
task-numbered production module or API names for new code; fabricate or infer T100 references;
use an empty source or old T109 successful writer as a fallback; rewrite historical artifacts
or approved task contracts; bypass the central risk or signer boundary; or add signing,
broadcast, key-loading, or plaintext Keystore decryption.
