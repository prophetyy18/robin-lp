# T066 — Build versioned threshold experiments and provisional candidate review

> Phase: `P06`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

## Dependencies

T064, T065

## Outcome

the experiment/review mechanism works; remaining final economic/risk
numbers are deliberately deferred until paper trading evidence exists.

## Deliverables

point-in-time train/validation/test and rolling walk-forward plan;
parameter-search manifest; PnL/profit probability/Expected Shortfall/boundary/time-
in-Range/fee/cost distributions; neighborhood stability and stress reports; an
immutable candidate-lock record, written before the test fold is read, freezing the
candidate version and the protocol it will be judged under — parameter-set version,
code revision, manifest hash, seed, declared split boundaries, cost assumptions and
elimination rules — with its content hash, the actor and the lock time; the experiment
harness writes that record, observes it, and refuses to read the test fold for a
candidate version that has none, so a change to any frozen field after the lock is a new
candidate version rather than an edit; provisional recommendation or `NO_TRADE`, always
carrying `EXPERIMENTAL_NOT_LIVE_APPROVED`.

## Acceptance

USDG cash is the primary benchmark; test data stays untouched until one
candidate is locked, the lock being the recorded candidate-lock artifact above, which the
harness must find for that candidate version before the test fold is read, so the
evaluation fold is seen once and after the lock (`DS-031`); all losing/rejected runs
remain; rerun is deterministic; parameter changes create a new version, including a
change to a field frozen by the lock; T066 output alone cannot satisfy T094.

## Must not

invent universal thresholds before data, retune on test, suppress no-trade
periods, select only the highest return, or turn a fixture/provisional value into a
product/live default.
