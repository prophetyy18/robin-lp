# T107 — Lock candidate identity, schema and registry revision

> Phase: `P06`
> Contract status: `OWNER_AMENDMENT_A0014`

## Dependencies

T065, T066, T068, T106, T109

## Outcome

the experiment/review mechanism retains every valid T066 guarantee while a candidate lock freezes
the registered strategy identity, parameter schema and registry revision that define the candidate.

## Deliverables

Preserve T066's point-in-time train/validation/test and rolling walk-forward plan, parameter-search
manifest, PnL/profit-probability/Expected-Shortfall/boundary/time-in-Range/fee/cost distributions,
neighborhood stability and stress reports, and provisional recommendation or `NO_TRADE` carrying
`EXPERIMENTAL_NOT_LIVE_APPROVED`.

Before the test fold is read, write and re-read an immutable candidate lock with content hash,
actor and lock time. Preserve every T066 frozen field—parameter-set version, code revision,
manifest hash, seed, split boundaries, cost assumptions and elimination rules; the predecessor
T105 manifest hash remains on historical locks only. The current lock freezes the stable
T068 strategy identity and version, registry revision/checksum, parameter-schema
identity/version/checksum and complete validated parameter values, plus the validated T109
manifest/report hashes, immutable T100 dataset reference/content hash, and simulation-evidence
schema/checksum/availability. It consumes those bindings without copying or republishing simulation
evidence. The search surface must be a
T106 schema-bound surface. Any change in identity, strategy version, registry revision, schema,
allowed range, code provenance, parameter value or another frozen field creates a new candidate
version and lock; the old candidate is never edited or reinterpreted under the new registry.

## Replacement and migration

- **Old code reachability:** version or replace `robinhood_lp.experiments.candidate_lock`, search and
  harness entry points. After cutover, the test-fold gate accepts only the registry-bound lock
  version. The T066 lock parser may remain solely as a read-only legacy parser; no current harness
  run may create or accept it as current evidence.
- **Historical data and artifacts:** retain all T066 locks, search manifests, rejected runs and
  reports byte-for-byte. A T066 lock or a lock bound only to a pre-T109 T105 manifest remains
  historical, exact-replay unavailable and ineligible as a current candidate. Mark old locks as
  legacy and preserve their hashes. Never backfill an
  unrecorded registry identity. Any additive migration record links the old hash to a separately
  validated registry revision and cannot convert already-seen test data into a fresh candidate.
- **Runtime cutover and rollback/fail closed:** deploy the new writer and reader as one gate. If the
  registry/schema revision or T109 manifest/dataset/evidence binding is missing, changed,
  incompatible or unavailable, refuse to read the test
  fold. Rollback stops candidate evaluation or uses the last compatible registry-bound version; it
  never falls back to the T066 lock for a new evaluation.
- **Downstream dependencies:** later CONTRACT amendments must replace T066 with T107 in T073 and
  T083 and in any other ordinary `PLANNED` consumer. The predecessor stays only as T107's declared
  replacement dependency and immutable history. T096 must carry T107's independently reviewed
  candidate-lock and old-path-unreachable evidence into the final matrix.
- **Security:** the lock carries identity and checksums, no secrets or credentials; it grants no
  paper/live permission and cannot satisfy T094. Replay evidence likewise grants no permission.
  Tampering, substitution and downgrade to the old
  lock format fail closed.
- **Verification:** retain all T066 positive, no-trade, deterministic and one-look tests; add changes
  to each new frozen field, including each T109 dataset/manifest/evidence binding, as independent
  new-version cases; negative missing/mismatched/tampered/downgraded registry and schema cases;
  current, legacy, evidence-unavailable and mismatch fixtures; and old-path-unreachable tests proving
  the current harness cannot evaluate with an old lock or consult T105 as current authority.

## Acceptance

USDG cash remains the primary benchmark; the test fold remains untouched until one candidate is
locked and the exact lock is written, re-read and verified. The lock binds all old and new frozen
fields, including the current T109 dataset/manifest/evidence checksums, and a change to any one
produces a distinct candidate version before the test fold can be read. Losing and rejected runs
remain, reruns are deterministic, legacy locks remain byte-identical and non-current, missing or
mismatched current evidence and predecessor-only locks fail closed, no current path reaches the
T105 publisher, and T107 output or replay evidence alone cannot satisfy T094.

## Must not

invent universal thresholds before data, retune on test, suppress no-trade periods, select only the
highest return, turn provisional values into product/live defaults, infer missing registry fields,
rewrite an old lock, republish simulation evidence, accept a pre-T109 T105-only or
evidence-unavailable lock as current, reuse test-fold exposure under a new registry identity, or
grant execution or promotion authority.
