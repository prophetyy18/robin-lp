# T032 — Implement checkpointed historical ingestion

> Phase: `P03`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

> Owner amendment (2026-09-16): implement the ADR-010 Robinhood-public +
> Alchemy-Free capability-driven route; do not assume a 10,000-block provider cap.

## Dependencies

T020, T022, T031

## Outcome

bounded scans resume without gaps or duplicate canonical events.

## Deliverables

range planner, durable checkpoint, explicit scanned-empty intervals,
retry ledger, run manifest, and deterministic normalization pipeline. Preflight
probes persist per-endpoint capabilities and a call/CU/time budget. One
pool-filtered topic0 OR query covers `Initialize`, `ModifyLiquidity`, `Swap`, and
`Donate`, plus inherited `ProtocolFeeUpdated`; Robinhood public RPC is the initial
wide-range log source and Alchemy Free supplies archive/block-pinned reads and
sampled verification. Either endpoint may fail over only within its measured
capability and remaining budget. The Robinhood request uses an explicit non-secret
application User-Agent. A cold start scans from the selected pool's registered
`Initialize` block through the requested end block; a shorter backtest start does
not truncate the reconstruction prefix. Only a previously qualified local
checkpoint permits suffix-only ingestion. Fetch one non-hydrated block header per
distinct event block and reuse it across events.

## Acceptance

kill/restart at each boundary and overlapping/concurrent-run tests
converge; every requested block is covered exactly once by a successful or
explicitly failed interval; failed intervals prevent completion. Fixtures cover
Alchemy's observed 10-block limit, Robinhood wide-range success followed by
adaptive split, HTTP 403 caused by a missing/blocked User-Agent, response-size
overflow, rate limiting, budget exhaustion, and provider failover without gaps.
The run manifest estimates and then records logical RPC calls, HTTP requests,
bytes, rows, provider units, elapsed time, and deviations from the preflight plan.
Tests distinguish cold-start history from warm incremental ingestion and reject a
checkpoint whose manifest, block hash, schema, decode version, or coverage prefix
does not match the requested pool and range.

## Must not

advance checkpoint before durable commit, infer empty coverage from an
empty table, continue past an irreducible failed block as “complete”, issue one
scan per event type when a combined filter suffices, or describe HTTP batches as
fewer RPC calls. Do not download hydrated blocks, all transactions, or all receipts
as part of ordinary pool-history ingestion.
