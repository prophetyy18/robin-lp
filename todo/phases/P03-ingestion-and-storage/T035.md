# T035 — Persist block-time evidence and wire real-mainnet ingestion

> Phase: `P03`

## Dependencies

T030, T031, T032, T033, T034

## Outcome

An operator can run one bounded historical ingestion for one approved V4 PoolKey against
the real Robinhood Chain mainnet endpoint, and the resulting dataset carries block-time
and parent-hash evidence pinned to canonical block headers, so the range can be ordered
in event time and independently re-checked.

This task closes the T030 / T031 / T032 clauses whose contracts already require a
per-event integer block timestamp and parent hash but whose physical implementation
never landed: the header record, the Parquet columns, the manifest header table, the
non-hydrated header source, and the production client that connects the read-only RPC
adapter to the ingestion router. It does not rewrite those contracts' text; it states
which of their clauses it closes: the T030 block / header / receipt context schema and
its common-field timestamp and parent-hash requirement, the T031 Parquet column and
manifest-row clauses that must physically carry them, and the T032 "Block header policy"
clause requiring one non-hydrated header per distinct event block.

The acquisition shape is fixed and must not drift: one pool-filtered range query per
planned sub-range, every event persisted with its `(block_number, transaction_index,
log_index)` position, and state rebuilt locally downstream. The dataset must be
sufficient for that local reconstruction with no per-block state query, and the run must
not pay per-block cost for a sparse event stream.

The shape is fixed by measurement, not preference. A read-only probe on 2026-09-17
against the public mainnet endpoint (chain id 4663, observed head block 65392511)
recorded the facts that decide it, carried in `docs/spec/protocol/PROVIDER_FACTS.md` and
ADR-012: one pool-filtered range query with the five-topic0 OR filter served a
1,000,001-block reference range in a single call (3739 events across 3266 distinct
blocks), while a full-chain-range five-topic0 OR query timed out (`-32000 log query timed
out`) and a single-event full-range query was rejected (`-32000 logs matched by query
exceeds limit of 10000`). Per-block scanning is therefore both contract-forbidden and
unusable in practice, and every block-header read must be justified by an actual pool
event. This task does not own adaptive range splitting (T032) or the reference-dataset
qualification (T036).

## Deliverables

1. Block-header persistence: a T030 logical header record keyed by
   `(chain_id, block_hash)` carrying `block_number`, `parent_hash` and `timestamp`; the
   T031 Parquet partition columns `block_timestamp` (uint64) and `parent_hash`
   (binary(32)); and a manifest table holding exactly one deduplicated row per distinct
   event block. The logical record, the Parquet columns and the manifest table are
   required together, not alternatives: the Parquet columns serve event-time ordering
   and replay, the manifest table serves dedup, coverage accounting and cross-checking.
2. A real `BlockHeaderSource` that calls `eth_getBlockByNumber(hex(n), false)`,
   deduplicates per distinct event block, and reuses one header across every event in
   that block. Its logical call count equals the number of distinct event blocks in the
   covered range, never the number of scanned blocks, and a block with no pool event is
   never fetched. Header requests are issued as JSON-RPC batches, measured as supported
   on both qualified endpoints and recorded in the provider-facts artifact, and the
   logical-call versus HTTP-batch split is reported. It
   must reject the `eth_getLogs` `blockTimestamp` field as a time source, because the
   2026-09-17 probe observed that field as `0x0` on every returned log, so block time
   must come from the header. A header that cannot be
   obtained halts the interval and must not set `complete=true`.
3. A production `EndpointClient` bridging `RpcAdapter.eth_get_logs` into the router's
   measured-capability and remaining-budget failover path. The primary endpoint carries
   the main scan; the secondary endpoint participates only within its own measured
   capability. The measured secondary capability (about 10 blocks per `eth_getLogs`
   call) and the HTTP 429 behaviour of rapid sequential calls are planning inputs to
   that routing, not assumptions the run may skip re-measuring.
4. A minimal read-only operator entry point (`python -m robinhood_lp ingest ...`) taking
   a configuration path, a data root, and an inclusive block range, and printing the run
   identifier plus the resulting `complete` state. It must not accept, read or forward
   any signing material. Its acquisition path issues no `eth_call`: the measured
   historical-state difference between the endpoints (the primary cannot serve state at
   the reference depth while the secondary can) is why block-pinned state reads belong to
   the qualification task T036 and to state reconstruction, never to ingestion.
5. The measured provider facts recorded as a machine-readable artifact under
   `docs/implement/protocol-artifacts/`, sourced from the planning-layer record in
   `docs/spec/protocol/PROVIDER_FACTS.md`, carrying retrieval time, chain id, endpoint
   alias, the observed block number, and the facts this contract depends on: the single
   result-bearing call that covered the reference range, the unusable
   `eth_getLogs.blockTimestamp` field, the observed timeout, result-count and HTTP 429
   failures, the secondary endpoint's per-call log-range capability, the JSON-RPC batch
   support measured on both qualified endpoints, and the historical-state availability
   difference that decides which endpoint may serve block-pinned `eth_call` reads.

## Acceptance

- one bounded range against the real mainnet endpoint completes with `complete=true` and
  zero uncovered intervals, and re-running the same range is idempotent: same normalized
  content hashes, unchanged partition set, no duplicate rows;
- every persisted event carries `block_timestamp` and `parent_hash`, and for every event
  block `(block_number, block_hash, parent_hash, timestamp)` equals the values read
  directly from `eth_getBlockByNumber` at validation time; `parent_hash` is contiguous
  inside the range;
- every persisted event carries its `(block_number, transaction_index, log_index)`
  position, no two rows share the same position, and the three header/time carriers are
  all present and consistent: the header record is resolvable by `(chain_id, block_hash)`,
  the Parquet partition exposes `block_timestamp` and `parent_hash`, and the manifest
  header table holds exactly one row per distinct event block;
- the header source resolves blocks far behind the chain head, including the pool's
  `Initialize` block, without falling back to a header-less record;
- no wall-clock value and no provider `blockTimestamp` value appears in any stored time
  field;
- an injected header-fetch failure ends the run non-complete with an explicit reason
  code, and a missing header is never silently defaulted to zero or to the request time;
- call-volume bound: over the covered range the run issues one logical `eth_getLogs`
  stream bounded by the plan's sub-range count plus adaptive splits, never one call per
  block; the deduplicated `eth_getBlockByNumber` count equals the number of distinct
  event blocks and no header is fetched for a block without a pool event; and no
  `eth_call` is issued during acquisition at all;
- the run result exposes the logical and HTTP call counts per method, so the bound above
  is checkable from the run's own output rather than from an operator's recollection;
- header retrieval is batched and accounted: the reported `eth_getBlockByNumber`
  logical-call versus HTTP-batch split reconciles with the deduplicated header count, and
  batching never lowers the reported logical-call count;
- request provenance never stores a credential-bearing URL.

## Must not

- sign, broadcast, or read key material; the Phase 0–8 boundary is unchanged;
- introduce or tune any economic or risk parameter;
- treat `eth_getLogs.blockTimestamp` as a time source or substitute wall-clock time for
  block time;
- widen to more than one pool, chain, or PoolKey;
- rewrite the text of the T030 / T031 / T032 / T033 / T034 contracts;
- infer coverage or contents from filenames, or mark a run complete over an uncovered
  interval;
- scan block by block, issue one `eth_getLogs` call per block, issue one
  `eth_getBlockByNumber` call per scanned block, fetch a header for a block that has no
  pool event, or call `eth_call` per block or per event;
- reconstruct pool state from RPC reads instead of from the ingested event stream.
