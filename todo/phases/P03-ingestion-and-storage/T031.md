# T031 — Implement append-only raw storage

> Phase: `P03`

## Dependencies

T030

## Outcome

T031 owns the **Parquet column layout, partition strategy, and
manifest / checkpoint / reorg-journal physical layout** for the
append-only raw partitions and SQLite manifest store. It carries
the decisions in ADR-002 forward into concrete columns, partitions,
files, and manifest rows, and it applies the field-semantics
refinement in ADR-010 on top of that physical layout.

- writes are atomic, deduplicated, verifiable, and recoverable;
- ADR-002 is the accepted storage decision and is not reopened in
  this contract. ADR-010 refines the **field semantics** inside
  ADR-002's two-layer structure (acquisition envelope / manifest
  fields, normalized event identity, normalized content hash) and
  does not replace the storage engine;
- T030 owns the **logical schema** (record types, field names,
  types, widths, identity, semantics). T031 does not redefine
  logical schema; it only fixes how those logical fields map to
  Parquet columns, partitions, files, and manifest rows such that
  every property T030 promises survives the physical encoding;
- acquisition provenance fields (endpoint alias, retrieval time,
  request interval, HTTP batch metadata) live in the raw
  acquisition envelope / manifest. The normalized event identity
  (T011 `EventKey`) and the normalized content hash are computed
  **without** those observational fields, so the same chain event
  fetched from A and from B produces the same normalized content
  hash while both raw acquisition envelopes are still retained and
  checksummed separately.

## Deliverables

- **Parquet column layout** for append-only raw partitions
  partitioned by `(chain_id, contract_address, event_name,
  block_range)`, justified by ADR-002 (append-only raw partitions,
  typed columns, schema/decode version) and by ADR-010 (separate
  raw envelope / manifest fields from normalized event identity and
  content hash):
  - raw evidence columns: original `topics` array, original `data`
    blob (hex), and the original JSON-RPC response wrapper for the
    log, retained alongside the typed columns without overwrite;
  - typed / normalized columns: the complete logical field set
    defined by T030, including common identity and per-event
    typed fields;
  - acquisition envelope columns: endpoint alias, retrieval time,
    request interval, and HTTP batch metadata (batch id, batch
    request index, batch response index when applicable). The raw
    acquisition provenance columns are observational and are
    excluded from the normalized event identity and from the
    normalized content hash input;
  - schema / decode version columns, matching the logical schema
    contract from T030.
- **Staging / atomic commit pattern** so a crash at any commit
  boundary leaves either the previous committed state or the
  complete new state and never an exposed half-written partition.
- **Manifest rows** (SQLite, per ADR-002) recording per partition:
  row count, block bounds (min / max block number and hash),
  partition file SHA-256 checksum, schema / decode version, and
  ingestion checkpoint (chain, contract, last successful block).
  Manifest accounting is split by:
  - endpoint alias;
  - logical RPC calls;
  - HTTP requests / batches;
  - response bytes;
  - normalized rows;
  - provider units when the provider reports them (e.g. Alchemy
    CU);
  - Parquet bytes written;
  - explicit scanned-empty intervals (block ranges requested and
    intentionally empty, recorded separately from failed or
    un-fetched intervals).
- **Reorg journal** (per ADR-002) marking orphan blocks,
  replacement blocks, and demotion reasons without destroying the
  audited raw evidence.
- **Event unique keys** built on T011 `EventKey`
  `(chain_id, block_hash, tx_hash, log_index)`. The normalized
  content hash is computed over the canonical serialization of
  the typed event body plus the canonical serialization of the
  `EventKey`; observational provenance fields are not part of the
  hash input.
- **Reader** that resolves a partition by `(chain_id,
  contract_address, event_name, block_range)`, checks the manifest
  SHA-256 against the file, surfaces manifest mismatch and
  corruption as errors, and never infers coverage or contents from
  filenames.
- Two raw acquisition envelopes from A and B are both appended
  and checksummed; the normalized content hash equality across
  providers never erases the raw envelopes.

## Acceptance

- repeat / overlap ingestion is idempotent: re-running an
  overlapping range produces the same normalized content hash and
  leaves the manifest and partition set in a state indistinguishable
  from a single successful run, while still preserving every
  raw acquisition envelope that was observed;
- a crash at every commit boundary (mid-partition write,
  mid-manifest row, mid-reorg journal append) leaves either the
  previous committed state or the complete new state, and never an
  exposed half-written partition or a manifest row that points at
  missing / partial bytes;
- corruption and manifest mismatch are detected on read: a
  partition whose SHA-256 does not match its manifest row, a
  manifest row whose partition file is missing, and a manifest row
  whose block bounds do not match the file content all surface as
  errors and prevent the reader from returning a qualified dataset;
- the same on-chain event fetched from two different endpoints at
  two different retrieval times yields the **same** normalized
  content hash, while both raw acquisition envelopes are still
  retained and checksummed;
- dedup is by T011 `EventKey` plus normalized content. Dedup is
  not driven by ingestion time, endpoint, block number alone, or
  filename. Conflicting observations (same `EventKey` but
  disagreeing normalized content) are retained as separate
  observations and halt dataset qualification instead of one
  silently overwriting the other;
- at least one representative short-range measurement justifies
  the chosen partition sizing and retention footprint for the
  measured data volume; the observed volume is recorded as a
  measurement and is not promoted to a universal constant for
  every future range, endpoint, or pool.

## Must not

- mutate or delete orphaned raw evidence. Reorg demotion must
  mark rows as orphan and record the reason in the reorg journal;
  the bytes themselves remain auditable;
- expose half-written partitions to the reader. A partition is
  only visible after its staging file is atomically renamed into
  place and its manifest row is committed;
- trust filenames as manifests. Coverage, contents, and integrity
  are decided from the SQLite manifest rows and the per-file
  SHA-256 checksum, not from partition filenames;
- reopen or replace ADR-002 in this task. Storage-engine or
  persistence-layer changes are revisited only when implementation
  proves the two-layer structure cannot satisfy requirements,
  matching the ADR-002 migration trigger;
- write a credential-bearing URL (any URL whose authority contains
  userinfo, or whose query string carries a secret-like key) into
  raw, normalized, manifest, or provenance storage. URLs are
  reduced to endpoint aliases sourced from configuration;
- weaken Acceptance in order to make a partial implementation pass.
  A failing acceptance clause is a contract gap, not a test bug.
