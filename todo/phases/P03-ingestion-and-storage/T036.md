# T036 — Qualify the real-mainnet reference dataset

> Phase: `P03`

## Dependencies

T035

## Outcome

The real-mainnet ingestion path is proven end to end on one pinned reference pool: the
dataset is qualified by a T034 completeness report with `complete=true`, its fidelity is
confirmed by an independently acquired sample, and the result is frozen as the
reproducible golden fixture that later phases compare against.

A dataset whose qualification report is missing, non-passing, or synthetic-only does not
satisfy Phase 4's entry condition.

This task consumes the T035 header/time deliverable and the T034 report; it closes its
own qualification clauses and does not restate or rewrite the T030 / T031 / T032 / T033 /
T034 contract text.

### Reference target

The reference pool and range are pinned by the Owner; they are not a planning choice and
must not be widened, swapped, or substituted:

- chain id `4663` (Robinhood Chain mainnet);
- PoolManager `0x8366a39cc670b4001a1121b8f6a443a643e40951`, StateView
  `0xf3334192d15450cdd385c8b70e03f9a6bd9e673b`;
- PoolKey `currency0` `0x5fc5360d0400a0fd4f2af552add042d716f1d168` (USDG, 6
  decimals), `currency1` `0x7dbf38976f6d3b9c529e7d9484a71898b409ee6a` (ZZZ, 18
  decimals), `fee` 28001, `tickSpacing` 280, `hooks` `0x0`;
- PoolId
  `0x6c614c38c65fea492f4cb2b90fd664f924a7b828c7384620662217e2e2df43ed`;
- inclusive reference range: blocks `54946237..55946237`.

A read-only probe on 2026-09-17 against the public mainnet endpoint (observed head block
65392511) measured that range as one pool-filtered `eth_getLogs` call covering the five
event types: 3739 events across 3266 distinct blocks — Initialize 1, ModifyLiquidity
578, Swap 3159, ProtocolFeeUpdated 1, Donate 0. The range is finalized history, so the
measured baseline is immutable: the qualified dataset records its own per-event-type
counts and distinct event-block count and compares them against the baseline, and any
difference is raised as a discrepancy rather than explained away. The baseline is a
comparison target, never evidence in place of the run's own report.

The measured baseline also records exactly one `Initialize` event inside the range, so
this range carries the reference pool's initialization and supports the cold-start
coverage rule without a wider scan.

## Deliverables

1. A qualified reference dataset for the pinned reference pool over the pinned inclusive
   range `54946237..55946237`, with its T034 machine report and `complete=true`, the
   endpoint mapping used to obtain it, the `PoolId` re-derived from the pinned `PoolKey`
   and checked against the pinned `PoolId`, and the recorded per-event-type counts and
   distinct event-block count compared against the 2026-09-17 baseline.
2. An independent fidelity check: sampled windows re-acquired through the second endpoint
   within that endpoint's measured per-call capability (about 10 blocks per `eth_getLogs`
   call as measured on 2026-09-17), compared per `EventKey` by normalized content hash,
   with both raw acquisition envelopes retained. The sample must cover the start, middle
   and end of the range, must satisfy T034's result-bearing comparison rule, and records
   its sample size plus the measured per-endpoint capability bounds. A window the second
   endpoint cannot serve is reported as a blocked check with the T034 reason code
   `cross_endpoint_sample_missing`; it is never skipped and never replaced by re-reading
   the first endpoint.
3. A block-pinned state spot check at the range end against StateView (`getSlot0`,
   `getLiquidity`) using an explicit block tag, issued to an endpoint that can serve
   historical state at that depth, plus the recorded golden values for the reference
   pool. The measured 2026-09-17 routing fact applies: the primary public endpoint cannot
   serve historical state at the reference depth while the second endpoint can, so an
   attempt against an endpoint that cannot serve it is recorded as a blocked check and
   never silently falls back to `latest`.
4. Failure-path evidence against the real endpoint: rate limiting (HTTP 429 on rapid
   sequential calls), response-size or result-count overflow (`-32000 logs matched by
   query exceeds limit of 10000`), query timeout (`-32000 log query timed out`), provider
   failover and budget exhaustion each produce their documented reason code and never a
   false `complete=true`.
5. The evidence pack recorded per the workflow's evidence convention, and the operator
   runbook for reproducing the run. The runbook states the endpoint routing explicitly:
   which endpoint carries the wide pool-filtered scan, which endpoint serves the sampled
   cross-validation and the block-pinned StateView read, and the measured per-endpoint
   capability bounds those choices rely on.

## Acceptance

- the report's `complete` is `true`, every interval state is `successful` or
  `scanned_empty`, and no interval is `failed` or `cancelled`;
- the qualified dataset is the pinned reference pool over the pinned range: the `PoolId`
  re-derived from the pinned `PoolKey` equals the pinned `PoolId`, a mismatch halts
  qualification, and the dataset's per-event-type counts and distinct event-block count
  are compared against the 2026-09-17 baseline with any difference raised as a
  discrepancy;
- the reference pool's `Initialize` block is named and lies inside the pinned range, so
  the cold-start coverage rule is satisfied by this range;
- per-`EventKey` normalized content hashes agree across both acquisitions for every
  sampled event of every sampled window, and any disagreement halts qualification instead
  of being reconciled by hand;
- the fidelity sample covers the start, middle and end of the range within the second
  endpoint's measured per-call capability, satisfies T034's result-bearing comparison
  rule, and records its sample size and the measured per-endpoint capability bounds;
- a sampled window the second endpoint cannot serve is reported as a blocked check with
  the T034 reason code `cross_endpoint_sample_missing`; it is never skipped silently and
  never replaced by re-reading the first endpoint;
- the qualification claims cross-endpoint agreement only; it must not claim
  independent-provider or third-party independence that was not directly evidenced;
- block-pinned StateView reads at the range end are issued to an endpoint that can serve
  historical state at that depth (the measured routing fact: not the primary public
  endpoint) and are integer-exactly consistent with the
  dataset's final observed state fields, or the task raises the mismatch rather than
  tolerating, widening or excluding it; a depth the endpoint cannot serve is a blocked
  check, never a `latest` substitution;
- the recorded golden values reproduce from a clean run, and the re-run leaves the
  manifest, checkpoint and partition set indistinguishable from the first run;
- a deliberately over-wide single request produces the documented reason code and never a
  silent partial success;
- the acquisition that produced the reference dataset satisfies the T035 call-volume
  bound: the run is range-based, its header fetches are deduplicated per distinct event
  block, and the only `eth_call` requests in the whole run are the explicitly enumerated
  block-pinned verification reads, whose count is recorded with the report;
- the observed call volume for the reference range is reported as measured, so a
  regression that pays per-block cost is visible rather than silent.

## Must not

- claim qualification from synthetic fixtures, from a single endpoint, or from an
  unverified report;
- compare the dataset against a `latest` read instead of a pinned block, or fall back to
  `latest` when the endpoint cannot serve the pinned depth;
- reconcile a cross-endpoint disagreement by choosing one side;
- treat budget exhaustion, a cancelled interval or a failed interval as coverage;
- widen, swap or substitute the pinned reference pool, `PoolId`, `PoolKey`, chain, or
  reference range, add a second pool or chain, or add any economic or risk parameter;
- treat a sampled window the second endpoint cannot serve as skipped, or substitute a
  re-read from the first endpoint for it;
- cite the 2026-09-17 measured baseline as qualification evidence in place of the run's
  own recorded counts and report;
- present sampled agreement as full-range verification;
- scan the range block by block, or use per-block `eth_call` for reconstruction; pool
  state is rebuilt locally and owned by the reconstruction tasks.
