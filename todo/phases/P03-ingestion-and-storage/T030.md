## Outcome

Raw evidence is **lossless** and normalized data is **evolvable**:

- raw JSON-RPC responses, topics, data blobs, response wrappers, and
  HTTP-batch metadata survive intact through the canonical
  serialization round trip;
- normalized records can be re-decoded or re-migrated under future
  schema/decode versions without losing or overwriting the original
  bytes;
- T030 in this phase defines the **logical schema** (record types,
  field names, types, widths, identity, and semantics). The Parquet
  column layout, partition strategy, and manifest/checkpoint/reorg
  journal physical layout are owned by T031 and follow ADR-002. T030
  does not bind the physical engine choice; it only constrains what
  every physical encoding must preserve;
- pre-existing unverified implementation under T030 (see Implementation
  status) is processed by the WORKFLOW.md migration rule and is not
  treated as prior phase approval.

## Deliverables

### Schemas

Logical schemas for:

- block / header / receipt context (a block, its parent hash and
  integer timestamp, and the receipt context needed to anchor logs);
- the V4 events `Initialize`, `ModifyLiquidity`, `Swap`, `Donate`, and
  the inherited `ProtocolFeeUpdated`.

For every event, the schema carries:

- **raw evidence** fields: the original `topics` array, the original
  `data` blob (hex), and the original JSON-RPC response wrapper (the
  raw bytes the server returned for that log) — written alongside,
  never overwritten by, the typed fields;
- **typed fields**: the complete pinned ABI values listed in ADR-010
  for that event. Signed amounts and signed liquidity deltas remain
  Python `int` with the exact width and sign the ABI defines; floats
  are rejected.

### Common fields (every event)

`chain_id`, `pool_manager` address, `pool_id` (the on-chain V4
`PoolId`), block number, block hash, parent hash, integer block
timestamp, transaction hash, transaction index, log index, removed
flag, endpoint alias, request interval, schema/decode version, and
retrieval time. Every field is required at the typed layer; raw
provenance may carry the optional ones.

`ProtocolFeeUpdated` keeps the same common-field surface; its event
body is the V4 `ProtocolFeeUpdated(bytes32,uint24)` payload from the
same pinned v4-core commit used by T021.

### Event fields (typed, pinned ABI)

Per ADR-010's normalized field set:

- `Initialize`: currencies, fee, tick spacing, hooks, `sqrtPriceX96`,
  tick;
- `ModifyLiquidity`: sender, lower/upper ticks, signed liquidity
  delta, salt;
- `Swap`: sender, signed `amount0`, signed `amount1`,
  `sqrtPriceX96`, active liquidity, tick, emitted LP fee;
- `Donate`: sender, `amount0`, `amount1`;
- `ProtocolFeeUpdated`: pool ID, packed protocol-fee value with
  exact integer semantics from the pinned core artifact.

### Schema/decode version and provenance

Every record carries a `schema_version` and a `decode_version` (the
ABI / event-derivation version used to produce the typed fields). The
schema/decode version is consumed by migration tests and by the
canonical content hash.

Ingestion provenance is split from the normalized event identity:

- **Acquisition envelope / manifest** holds observational fields:
  endpoint alias, retrieval time, request interval, and HTTP batch
  metadata (batch id, batch request index, batch response index when
  applicable). The envelope is append-only; one log may appear in
  multiple envelopes when fetched from different endpoints;
- **Normalized event identity** is the T011 `EventKey`
  `(chain_id, block_hash, tx_hash, log_index)`. Two records from
  different endpoints with the same `EventKey` compare equal as
  normalized events;
- **Normalized content hash** is computed over the canonical
  serialization of the typed event body plus the canonical
  serialization of the `EventKey`. Acquisition provenance
  (endpoint alias, retrieval time, request interval, HTTP batch
  metadata) is excluded from the hash input so the same chain event
  fetched from A and B produces the same content hash;
- the **raw acquisition provenance**, including any URL with
  credentials, is **never** written. URLs are reduced to endpoint
  aliases sourced from configuration; any code path that would
  record a credential-bearing URL must refuse to write and surface
  the violation.

### T021 pinned artifact and drift tests

Extend the T021 pinned artifact and the selector/topic drift test so
that `ProtocolFeeUpdated(bytes32,uint24)` is asserted against the
same pinned v4-core commit as the rest of the V4 events. Drift in
either the event selector (topic0) or the topic/data layout of
`ProtocolFeeUpdated` fails the test, matching the existing T021
treatment of the other V4 events.

### Schema-v1 migration

A migration path exists from schema-v1 records to the current
schema. Old records are treated as migration fixtures, not as proof
that the amended contract is already satisfied. The migration is
tested with at least one unknown-field record and at least one
explicit old-version record replayed through the current decoder.

## Acceptance

- a raw JSON → normalized record → canonical serialization →
  normalized record round trip preserves every source byte of the
  raw fields, topics, data blob, and response wrapper;
- compatibility and migration tests cover unknown fields in incoming
  records and at least one old schema/decode version replayed
  through the current decoder without data loss or silent field
  drift;
- fixtures assert exact sign and width semantics (signed amounts,
  signed liquidity deltas, integer widths from the ABI) and a
  deterministic global ordering by
  `(block_number, transaction_index, log_index)` for any list
  surface that exposes more than one record;
- the same on-chain event fetched from two different endpoints at
  two different retrieval times yields the **same** normalized
  content hash while still retaining both raw acquisition envelopes;
- two distinct raw acquisition provenance records are still
  preserved per re-fetched event (the cross-provider equality of
  the normalized hash must not erase the raw envelopes);
- same-height fork logs remain distinct by block hash: the
  normalized identity and content hash differ because the
  `EventKey.block_hash` differs, even when the block number and
  the `(tx_hash, log_index)` pair would otherwise collide;
- request provenance never contains a credential-bearing URL;
  this rule is asserted by a dedicated test that fails the build
  if any path under the schema writes a URL containing a userinfo
  segment or a secret query parameter.

## Must not

- overwrite raw field values with decoded or display values at any
  layer;
- store integers as floats, or accept float inputs where the ABI
  requires an integer width or signed/unsigned semantic;
- make token metadata (symbol, name, decimals) required on any
  record — display metadata may be partial or absent;
- write a credential-bearing URL (any URL whose authority contains
  userinfo, or whose query string carries a secret-like key) into
  raw, normalized, manifest, or provenance storage;
- collapse two observational acquisitions of the same event into
  one envelope — the per-endpoint envelopes must be retained and
  checksummed;
- mutate the existing pre-existing unverified implementation in
  `src/robinhood_lp/storage/schema.py` (or its tests) outside the
  T030 contract or attempt to fast-forward that code into
  `APPROVED` without an independent Reviewer verdict on the T030
  candidate commit.
