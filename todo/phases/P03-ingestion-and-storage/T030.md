# T030 — Define versioned raw and normalized schemas

> Phase: `P03`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

> Owner amendment (2026-09-16): ADR-010 fixes the A+B free ingestion path and
> the minimum provenance/normalized field set below.

## Dependencies

T011, T021

## Implementation status

V1 dataclasses and canonical JSON serialization exist; dependency
verification, reconstruction into typed records and real old-version migration tests remain open.

## Outcome

raw evidence is lossless and normalized data is evolvable.

## Deliverables

schemas for block/header/receipt context and V4 `Initialize`,
`ModifyLiquidity`, `Swap`, `Donate`, and inherited `ProtocolFeeUpdated`; raw
topics/data/response fields alongside typed fields; schema/decode version and
ingestion provenance. Common fields include chain/PoolManager/PoolId, block
number/hash/parent/timestamp, transaction hash/index, log index, removed flag,
endpoint alias and request interval. Event fields include the complete pinned ABI
values listed in ADR-010; signed amounts and liquidity deltas remain integers.
Extend the T021 pinned artifact and selector/topic drift test with
`ProtocolFeeUpdated(bytes32,uint24)` from the same pinned v4-core commit. Request
provenance never contains a credential-bearing URL. Existing schema-v1 records
are treated as migration fixtures, not as evidence that this amended contract is
complete.
The schema separates an append-only acquisition envelope from canonical normalized
content: endpoint alias, retrieval time, request interval and HTTP batch metadata are
observational provenance, while normalized event identity uses T011 `EventKey`
`(chain_id, block_hash, tx_hash, log_index)` and compares equally across providers.

## Acceptance

raw JSON → normalized → canonical serialization round trip loses no
source bytes; compatibility/migration tests cover unknown fields and old versions;
fixtures assert exact sign/width semantics and deterministic ordering by
`(block_number, transaction_index, log_index)`. Re-fetching identical logs from
different endpoints/times produces the same normalized content hash while retaining
both raw provenance observations; same-height fork logs remain distinct by block hash.

## Must not

overwrite raw values with decoded/display values, store integers as
float, or make token metadata required.

## References

R4, R9, ADR-010, ADR-011.
