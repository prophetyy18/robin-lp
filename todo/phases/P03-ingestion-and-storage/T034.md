# T034 — Produce data-quality and completeness reports

> Phase: `P03`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

> Owner amendment (2026-09-16): qualify ADR-010 routing, budget, and sampled
> A+B agreement as part of dataset completeness.

## Dependencies

T032, T033

## Outcome

downstream code consumes only explicitly qualified datasets.

## Deliverables

machine/human reports for range coverage, block/hash gaps, duplicate/
misordered logs, unknown pools, decode errors, impossible values, stale endpoints,
metadata failures, and cross-provider/subgraph discrepancies.
The report includes the preflight/actual call budget, endpoint capability snapshot,
provider-to-interval provenance, response/storage volume, and deterministic
cross-provider sample selection with compared block hashes and logs.
The report records any known common operator/upstream infrastructure and calls the
result cross-endpoint—not independent-provider—agreement unless independence has
separate evidence.

## Acceptance

seeded defect fixtures trigger the correct reason code; `complete=true`
requires zero unexplained gaps/errors, no exhausted budget, successful required
A+B samples, and records dataset manifest checksum. Empty selective capability
probes demonstrate range acceptance only and never count as event completeness.
For a cold start, coverage begins at the selected pool's registered Initialize
event; for a warm run, the report names and verifies the qualified checkpoint and
the complete suffix. A backtest-window-only download without either basis is
incomplete even when every requested window block was scanned.

## Must not

let warning counts disappear in aggregates or treat a third-party
match as proof when raw chain evidence is incomplete.

## References

R12, R13, ADR-010.
