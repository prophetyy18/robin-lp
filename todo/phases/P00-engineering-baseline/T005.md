# T005 — Verify document citations against the repository

> Phase: `P00`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-19`

## Dependencies

T003

## Outcome

a binding document that cites a module path, a qualified symbol, a requirement
identifier or a task identifier which does not exist in this repository fails a
machine check, so a citation that has gone stale cannot outlive the code, the
identifier or the task it points at.

## Deliverables

1. An offline, deterministic checker (a `tests/` module plus any helper under
   `tools/`) that resolves every backticked token in a declared document set
   covering `README.md`, `CLAUDE.md`, `AGENTS.md`, `docs/**/*.md`,
   `todo/README.md`, `todo/WORKFLOW.md` and `todo/phases/**/*.md`:
   - a dotted name whose first component is `robinhood_lp`: as a module or
     package under `src/robinhood_lp/`, or, when its longest module prefix
     resolves, as an attribute that module defines or exports. A dotted name on a
     row of the `docs/spec/architecture/ARCHITECTURE.md` §2.2 mapping whose Task
     column names a task that is not `APPROVED` is recorded as planned and may be
     absent;
   - a two-part name whose first part is a class, enum or module defined under
     `src/robinhood_lp/` and whose second part is not a source-file extension: as
     a member that definition provides;
   - every `Txxx` identifier: as a task in `todo/config.yaml`, and, inside a §2.2
     row, as naming the successor of a task that carries `superseded_by`;
   - every requirement identifier of the families defined in
     `docs/intent/PROJECT_GOALS.md`,
     `docs/spec/product/ASSET_ADMISSION.md`,
     `docs/spec/product/WEB_CONSOLE.md`,
     `docs/spec/strategy/STRATEGY_ECONOMICS.md`,
     `docs/spec/operations/OPERATOR_CONTROL.md`,
     `docs/spec/strategy/LP_METRICS.md`,
     `docs/spec/research/DATASET_AND_EVALUATION.md` and the `todo/README.md` §5
     reference catalogue: as an identifier that its owning document defines, with
     a family pattern ending in a hyphen and an asterisk requiring at least one
     defined identifier in that family;
   - the Tasks list of every phase README under `todo/phases/`: as exactly the
     task identifiers whose `phase` in `todo/config.yaml` is that phase.
2. A machine-readable finding list naming the document, the line and the
   offending token, and a closed exception list in
   `docs/implement/ci/suppressions.toml` carrying `rule`, `reason`, `owner` and
   `expiry` per entry. An unlisted failure is fatal, and an exception entry that
   no longer matches a finding is itself fatal.
3. The check wired into CI as a required check, without weakening an existing
   job.

## Acceptance

the checker passes on the committed repository and runs as a required CI check;
each of the five resolutions above has a seeded regression that fails the check,
committed beside it, because a check that never fires is indistinguishable from
one that passes (`tests/test_documentation_links.py` is the pattern, including
its explicit can-it-fail test); a missing or empty document set, an unreadable
exception entry, an unparsable §2.2 row and an empty scan each fail closed
instead of being skipped; the exception list is printed with the finding list, so
a reviewer sees every deviation and its expiry.

## Must not

add a third-party dependency or require network access; skip, xfail or otherwise
step past a finding, or delete a citation, to make the suite pass; treat a
planned module path as a finding, or treat an existing finding as planned because
some task exists; weaken an existing CI job, test or assertion; edit Intent,
Spec, another task's contract, `tools/workflow/`, `.claude/`, `todo/schemas/` or
`todo/config.yaml`; repair a finding outside `tests/`, `tools/` and
`docs/implement/` — a finding in a path this task may not write is reported and
routed, not patched.
