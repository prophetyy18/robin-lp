# T006 — Enforce the layer dependency direction in CI

> Phase: `P00`
> Contract status: `OWNER_PLAN_EXTENSION_2026-09-19`

## Dependencies

T003

## Outcome

an import that contradicts ADR-006's declared direction, and a module-to-layer
assignment that `docs/spec/architecture/ARCHITECTURE.md` §2.2 and the enforced
graph disagree about, fail CI instead of being noticed only in review.

## Deliverables

1. A machine-readable layer map covering every module under `src/robinhood_lp/`:
   each entry names the layer from the §2.1 table that the module belongs to,
   expressed as a package default plus explicit per-module overrides. A module
   may need its own entry — `robinhood_lp.discovery` is the case that exists
   today, holding both a registry and a capability prober.
2. An offline, deterministic import-graph check, parsed from the sources with
   the standard library's `ast` and never imported or executed, that fails on:
   - an import from a lower layer to a higher one, in the order ADR-006
     enumerates (protocol/domain, rpc, storage, reconstruction, features, then
     strategy and backtest as the one tier that ADR-006 writes as a single
     entry, then risk, then execution), with `application / orchestration`
     placed where ADR-006's allowed-shape diagram places it: above strategy,
     risk and execution, below presentation;
   - an import cycle between two packages;
   - an import of `time`, `random` or another unseeded clock inside the
     protocol, replay, features, strategy or backtest modules;
   - a module the map does not classify.
3. The agreement check between the map and §2.2: every module path that exists
   under `src/robinhood_lp/` and appears in a §2.2 row is classified by the map
   with exactly that row's layer, so a layer changed in either place without the
   other fails.
4. A documented, closed exception list in `docs/implement/ci/suppressions.toml`
   carrying `rule`, `reason`, `owner` and `expiry` per entry, plus a finding
   report naming the module, the imported module, the layer pair and the source
   line, and the raw edge list so a reviewer can re-derive the graph. The
   `robinhood_lp.config` package is today's declared case: ADR-006's ten layers
   contain no platform layer, and its own migration trigger reserves one for a
   new ADR, so the exception cites that clause and carries an expiry rather than
   this task inventing a layer.
5. The check wired into CI as a required check, without weakening an existing
   job.

## Acceptance

the check passes on the committed repository and runs as a required CI check;
each rule in deliverables 2 and 3 has a seeded regression that fails the check,
committed beside it, because a check that never fires is indistinguishable from
one that passes (`tests/test_documentation_links.py` is the pattern, including
its explicit can-it-fail test); an unclassified module, an unreadable exception
entry, an empty module set and an unparsable §2.2 row each fail closed instead
of being skipped or defaulted; an exception entry that no longer matches a
finding is itself fatal; the reported edge list reproduces the graph the check
enforced.

## Must not

import or execute project modules at check time, or add a third-party
dependency or a network read; delete a module, an import or a §2.2 row to make a
rule pass; relax the tier order, the layer map, §2.1 or §2.2 to make a violation
disappear; edit `docs/spec/` to resolve a drift — a row that disagrees with the
repository is reported and routed; change product behaviour or a public
interface in `src/`; skip, xfail or otherwise step past a finding; weaken an
existing CI job, test or assertion; edit Intent, another task's contract,
`tools/workflow/`, `.claude/`, `todo/schemas/` or `todo/config.yaml`.
