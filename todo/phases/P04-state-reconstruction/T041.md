# T041 — Reconstruct tick-liquidity state

> Phase: `P04`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

> Owner amendment A0002 (2026-09-18): tick and liquidity reconstruction is per pool
> over that pool's own qualified window; a pool whose `Initialize` is not inside its
> window is not reconstructed.

## Dependencies

T040, T037, T038

## Input scope

Tick and liquidity reconstruction is per pool, over that pool's own qualified
window and data root (T038). Reconstruction state is never merged, shared or
carried across pools, and a pool with no qualified dataset is not reconstructed.

A pool that T038 reports as `pool_init_outside_window` and excludes from the
qualified dataset is **not** reconstructed: this task must not reconstruct it from
a partial window, from a later-state bootstrap, from a neighbouring pool's data, or
by widening the window, and the run records the exclusion instead of a partial
crossing history.

## Outcome

initialized ticks and active-liquidity crossings obey V4 invariants.

## Deliverables

gross/net tick updates, bitmap/initialized state, crossing logic,
position key treatment, and invariant checks.

## Acceptance

add/remove/poke, boundary crossing both directions, same-block multi-
action, max liquidity, negative gross, spacing and overflow vectors match core.

## Must not

derive owner inventory from pool liquidity events or assume one event
equals one user position lifecycle.
