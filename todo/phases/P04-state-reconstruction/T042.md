# T042 — Validate replay against independent chain state

> Phase: `P04`
> Contract status: `FROZEN_FROM_BASELINE_6C31778`

> Owner amendment A0002 (2026-09-18): the heterogeneous pool set is the two pools
> T038 qualifies, historical-state reads are explicitly routed, and the comparison
> carries recorded cost bounds and reuses T037's reconciliation.

## Dependencies

T041, T038

## Outcome

replay correctness is measured, not asserted.

## Comparison scope, routing and bounds

1. **Pool set.** The "heterogeneous pools" below are the pools included in T038's
   qualified dataset: the re-acquired ZZZ/USDG reference pool and the Owner-pinned
   second pool. Each is validated against its own data root and its own replay
   output, per pool. That clause is satisfied by those two datasets; it is not
   deferred to an unspecified future acquisition source, and one pool's agreement
   is never presented as the other pool's result.
2. **Historical-state routing.** Every block-pinned StateView read is issued to an
   endpoint that can serve historical state at the pinned depth (the measured
   routing asymmetry is recorded in `docs/spec/protocol/PROVIDER_FACTS.md`). An
   endpoint that cannot serve that depth produces a **blocked check** with a
   recorded reason code and the height at which it occurred; it is never
   substituted by `latest`, by an unpinned read, by another height, or by a
   post-hoc re-read of a different endpoint. Blocked checks are reported as
   coverage the run did not obtain, and each blocked check records the reason code
   from the T034 reason-code set (the P03 precedent for an unservable pinned
   historical-state read is `cross_endpoint_sample_missing`), the height, and the
   endpoint alias that could not serve it.
3. **Recorded bounds.** The runner fixes and records, before it runs, at least: the
   number of heights compared per pool, the per-height read list (which StateView
   methods are read at each height), and a logical-call and compute-unit budget
   ceiling. The recorded heights and read list are the acceptance surface, so a run
   cannot silently reduce coverage to stay inside the ceiling: a run that would
   exceed the ceiling stops and reports the exhaustion.
4. **Input reconciliation.** The per-partition `event_index`-versus-Parquet
   reconciliation is the one T037 delivers. This task consumes its result for both
   pools and does not re-implement, re-derive or relax it.

## Deliverables

block-pinned StateView comparison runner and discrepancy report for
slot0, active liquidity, ticks/bitmap, fee growth where supported; the
recorded comparison bounds (heights per pool, per-height read list, logical-call
and compute-unit budget ceiling), and the blocked-check records for heights or
endpoints that could not serve a pinned read.

## Acceptance

multiple heights and heterogeneous pools match exact integer fields: both pools of
the comparison scope above, each against its own data root and replay output, over
the recorded per-height read list; the number of heights compared, the per-height
read list, and the logical-call and compute-unit budget ceiling are recorded, and a
run that would exceed the ceiling reports the exhaustion instead of reducing
coverage; a height or endpoint that cannot serve a block-pinned read is reported as
a blocked check, never as a pass and never as a `latest` substitution; any
tolerated derived decimal lists formula and bound; unexplained mismatch makes
dataset ineligible for Phase 5.

## Must not

validate against the same replay output, `latest`, or only one favorable
checkpoint; substitute `latest`, an unpinned height or another height for a
block-pinned read an endpoint cannot serve at the pinned depth, or count an
unserved read as a pass.
