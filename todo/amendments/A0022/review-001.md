## Summary

The Owner-directed MarketState/RunState/ReplayFrame split, canonical-dataset/no-market-copy rule, no-strategy-rerun rule, sparse-checkpoint allowance, atomic publication, legacy-unavailable behavior, and prohibitions on parallel replay/backtest/accounting authorities are directionally correct. Mechanical review found no new gate regression: workflow validate, import-graph, acceptance and git diff --check pass; the sole citation finding is the same pre-existing unresolved T069 module-path finding on the base and candidate. The amendment is not yet contract-complete, however. It does not define how T061's timestamp/stage-ordered simulation transitions are mapped to the chain-event MarketCursor or which post-transition boundary RunState at a cursor denotes, so same-block and delayed-fill histories can produce more than one plausible state. It also defines MarketState only through T040/T041 even though those paths explicitly do not reconstruct fee-growth globals and the approved T104 fee-growth projection is the existing historical fee primitive used by the affected Web views. Finally, collateral and migration assessment are incomplete: current threat controls and several traceability rows still name T105/T069 as current without T109, and T109 does not explicitly prove compatibility of the already-approved T101/T106 consumers with the changed manifest schema/new-write path. These are specification and impact-completeness defects, not Owner ambiguities.

Require every persisted run transition/checkpoint to bind to the exact canonical MarketCursor (not infer it later from the T061 integer timestamp), define a deterministic intra-cursor order for decision/risk/latency/fill and multiple same-block events, and state whether RunState(run_id, cursor) is the state after all run transitions at or before that cursor. T040/T041 do not reconstruct feeGrowthGlobal (the implementation states that directly), while T104 is the approved dataset/reconstruction-bound fee-growth projection consumed by T088/T103. Define the MarketState field boundary: either include T104's cursor-addressable fee-growth state as the existing projection, or state that fee growth/range-fee queries are a separate T104 projection composed by the read model. In either case, require T088/T103 amendments to retain T104 provenance and exact-fee semantics, prohibit a replacement fee implementation, and add T104 to the relevant dependency/traceability/verification path where it is consumed.

Update the current-control references in docs/spec/security/THREAT_MODEL.md (notably T-17, T-21 and the controls matrix) and the existing TRACEABILITY rows for G-DATASET-01, G-BACKTEST-RUN-01, G-BACKTEST-RESULT-01 and other goals T109 takes over so T109 is the current delivery and T069/T105 remain predecessor evidence.
